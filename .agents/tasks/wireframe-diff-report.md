# ワイヤーフレーム差異レポート

生成日時: 2025-07-05  
対象ワイヤーフレーム: #01〜#10  
比較対象実装: `app/src/` 配下の全コンポーネント

---

## 修正した差異

### #06 エディタ詳細モード / Header.tsx — モードトグルのアクティブ色
- **差異**: ワイヤーフレームでは「くわしい」ボタンのアクティブ背景色が `#374151`（ダーク）だが、実装では `#5D9C3B`（グリーン）になっていた。
- **採用した解決策**: `Header.tsx` を修正し、`mode === 'advanced'` 時の「くわしい」ボタンに `bg-[#374151]` を適用。これにより「かんたん（緑）」と「くわしい（ダーク）」が視覚的に区別される。

### #07 ホーム画面（ja-kids）/ Header.tsx — 言語セレクタのスタイル
- **差異**: ワイヤーフレームでは `ja-kids` ロケール時の言語セレクタがより大きく（font-size: 1rem、font-weight: 600）、緑ボーダー（`2px solid #5D9C3B`）付きだったが、実装では通常サイズのグレーボーダーのみ。
- **採用した解決策**: `Header.tsx` で `locale === 'ja-kids'` 時に条件クラスを適用。対象ユーザー（小学生低学年）のアクセシビリティ向上のため修正。

### #08 状態グラフ / StateGraph.tsx — 状態ごとの削除ボタン
- **差異**: ワイヤーフレームでは左パネルの各状態行に「✕」削除ボタンがあるが、実装では未実装だった。
- **採用した解決策**: `StateGraph.tsx` の各状態アイテムをラッパー `div` に変更し、選択ボタンと削除ボタン（`✕`）を並べた構造に修正。削除の実処理は Phase 3 で実装予定（現時点は no-op）。

### #08 状態グラフ / StateGraph.tsx — キャンバスヒントとズーム・リセットコントロール
- **差異**: ワイヤーフレームにはキャンバス上部に「ドラッグ可能」ヒントテキスト、右下にズーム・リセットボタンがあったが、実装では未実装だった。
- **採用した解決策**: `StateGraph.tsx` のキャンバスラッパーに `position: relative` ベースでヒントオーバーレイ（左上）とコントロールオーバーレイ（右下）を追加。ズームは Phase 3 で実装予定（現時点はボタンのみ表示）。

### #09 外観エディタ / AppearancePanel.tsx — 2ペインレイアウト（3Dプレビュー + プロパティ）
- **差異**: ワイヤーフレームでは左ペインに3Dプレビュー＋カメラコントロール、右ペインにプロパティタブを配置した2ペイン構成だったが、実装はプロパティタブのみの1ペイン構成だった。
- **採用した解決策**: `AppearancePanel.tsx` を2ペイン構造に全面改修。左ペイン（`PreviewPane` コンポーネント）に3Dプレビュープレースホルダー＋カメラコントロールボタン（⟳ 回転リセット、前面、側面、上面）を追加。Babylon.js による実際のレンダリングは Phase 3 で実装予定。

### #10 外観エディタ（テクスチャ）/ AppearancePanel.tsx — テクスチャタブ時のUVマップ左ペイン表示
- **差異**: ワイヤーフレームではテクスチャタブ選択時に左ペインが3DプレビューからUVマップビューに切り替わる構造だったが、実装ではUVマップがテクスチャパネルの縦スクロールの中に埋め込まれていた。
- **採用した解決策**: `AppearancePanel.tsx` でテクスチャタブ選択時に左ペインを `UvPane`（UVマッピングビュー）に切り替えるよう修正。ズームアウト/リセット操作は `AppearancePanel` で状態管理し `UvPane` に渡す構成に変更。

### #10 外観エディタ（テクスチャ）/ AppearancePanel.tsx — テクスチャバリアントセクション
- **差異**: ワイヤーフレームの詳細モードにはテクスチャバリアント（variant_1 / variant_2）の一覧・編集・追加セクションがあったが、実装では未実装だった。
- **採用した解決策**: `TextureSlotPanel` に `テクスチャバリアント` セクションを追加。シンプルモードではガイドメッセージを表示、詳細モードではバリアントカード（説明・使用スロット・削除ボタン）と「＋ バリアントを追加」ボタンを表示。

### #10 外観エディタ（テクスチャ）/ AppearancePanel.tsx — スロット削除ボタン・追加ボタンの詳細モード限定化
- **差異**: ワイヤーフレームではスロットの削除ボタン（✕）とスロット追加ボタンが詳細モードのみ表示だったが、実装ではスロット追加ボタンが常に表示されていた。
- **採用した解決策**: 両ボタンを `mode === 'advanced'` の条件付きレンダリングに変更。

### i18n（ja.json、en.json）— 不足していた翻訳キーの追加

  - `editor.appearance.texture.variantAdvancedOnly`

## 実装を優先した差異（設計変更）

### #03 ウィザード Step 2 — フォームフィールドの順序
- **差異**: ワイヤーフレームはアドオン名（ID）→ 表示名の順だったが、実装は表示名 → アドオン名（ID）の順になっている。
- **理由**: 実装では表示名の入力からIDを自動補完する UX フローを採用（`toId()` 関数）。ユーザーは技術的なIDより表示名を直感的に先に考えるため、この順序の方が UX 合理的。ワイヤーフレーム設計後に発見された改善点として維持。

### #08 状態グラフ — 詳細モード専用タブ
- **差異**: ワイヤーフレーム #08 は状態グラフをシンプル/詳細の両モードで表示可能な設計だったが、実装では詳細モード専用タブとして配置している。
- **理由**: 状態グラフは Molang クエリや遷移条件など高度な概念を扱う機能。シンプルモード（初心者・子ども向け）には不要であり、詳細モード専用にすることでシンプルモードの UX がシンプルに保たれる。

### 全画面 — フッターなし
- **差異**: ワイヤーフレームにはバージョン情報のフッターがあるが、実装には存在しない。
- **理由**: ワイヤーフレームのフッター（`v0.1.0 — ワイヤーフレーム（開発中）`）はワイヤーフレーム制作上のアノテーションであり、プロダクション実装には不要と判断。

### ヘッダー — コントロールの左右配置順序
- **差異**: ワイヤーフレームでは言語セレクタ → モードトグルの順だったが、実装はモードトグル → 言語セレクタの順。
- **理由**: 一般的な Web アプリケーションのパターンとして言語セレクタを右端に配置する慣習に沿った実装。機能的な影響はなく、両方の順序で視覚的に問題ない。
