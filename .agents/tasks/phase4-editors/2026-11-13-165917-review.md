All Phase 4 editors are implemented and wired. Build exits 0, 212 tests across 30 test files pass. The diff delivers every acceptance criterion from the plan. Two cosmetic deviations from the plan spec do not affect correctness.

All 7 ja-kids appearance keys are present in `ja-kids.json` exactly as specified. ## StatusPanel spec deviation

The plan table specifies `step: 0.5` for `attackDamage`. The implementation uses `step: 1`. This means the number input and range slider advance in whole numbers only, losing the ability to set damage values like 2.5 or 3.5. The default value of `3` matches the plan. This is confirmed in `STATUS_ROWS` at line 30–37 of `StatusPanel.tsx`.

The `movementSpeed` emoji is `👟` (sneaker) rather than `🏃` (runner). Purely cosmetic.

## StateGraph Variables and Event Triggers

Both sections render only when `mode === 'advanced'`. The variables list supports add/edit/delete with name (font-mono) and defaultValue (number) inputs. Event triggers split into `on_entry` and `on_exit` sublists, each with their own Add button. All i18n keys (`variables`, `variablesName`, `variablesDefault`, `addVariable`, `eventTriggers`, `onEntry`, `onExit`, `addEvent`) are present in both `ja.json` and `en.json`.

## RecipeEditor tab structure

Three tabs — Shaped, Shapeless, Furnace — use the ARIA tab pattern with `role="tablist"`, `role="tab"`, `aria-selected`, and `aria-controls`/`id` pairs. `ShapedRecipePanel` renders a 3×3 grid with slot selection via click and inline input. `ShapelessRecipePanel` manages a dynamic ingredient list capped at 9. `FurnaceRecipePanel` exposes four fields (input/output/cookTime/experience). Cook time defaults to 200, experience to 0.7, matching the plan.

## LootTableEditor accordion

Initial state has one pool (rollsMin=1, rollsMax=2) with one diamond entry. Pools use a toggle-based accordion via `expandedPoolIds` set state. The header shows pool number, roll range, and a delete button. The expanded body shows roll min/max inputs, an entries table with type select/name/weight/count inputs per entry, and a dashed "Add Entry" button. A dashed "Add Pool" button sits outside the accordion list.

## SpawnRulesEditor filters

Implements all three required sections: biome filter (chip list with Enter-to-add input + per-chip delete), difficulty filter (three checkboxes, all checked by default), and population controls (weight, groupMin, groupMax). The time-of-day section (Dawn/Day/Dusk/Night) is gated on `mode === 'advanced'`, matching the plan.

## AnimationControllerEditor layout

Adds an identifier bar above the 3-pane area, pre-filled with `'controller.animation.my_mob.general'`. The right panel extends the StateGraph pattern with a per-state animations list (each animation is an editable string input with a delete button). Variables and Event Triggers sections are always visible here, unlike StateGraph where they are advanced-mode-only. Initial state has three nodes (`default`, `walk`, `attack`) with two transitions, each node carrying an animations array.

## SoundEditor toggles

`@radix-ui/react-switch` is used for `is3D` (checked by default) and `loop` (unchecked by default) toggles, with accessible `aria-label` attributes. The category `<select>` iterates `CATEGORY_OPTIONS` with `t('sound.categories.xxx')` as display labels. The file list supports add/edit (path, volume, pitch) and delete per file.

## Test coverage

FEAT-004 adds 193 new tests across 29 new test files, reaching 212 total. `recipeUtils.spec.ts` has 8 cases covering `isValidItemId` and both JSON builders. `lootTableUtils.spec.ts` has 6 cases covering weight totals, probability (including divide-by-zero guard), and JSON structure. Component specs for `StatusPanel`, `RecipeEditor`, `LootTableEditor`, `SpawnRulesEditor`, and `AnimationControllerEditor` are present. The `happy-dom` environment is enabled in `vite.config.ts` with a central setup file mocking `react-i18next` and `uiStore`.
