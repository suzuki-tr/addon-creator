# Phase 3 UX Implementation (feature/phase-3-ux)

Five commits ship the full Phase 3 scope: three bugfixes from Phase 2 findings (B-1), a new 3-column editor layout with JsonPreviewPanel, ComponentPanel, StateGraph, and AppearancePanel (B-2 through B-4), the ja-kids home variant (B-5), full locale coverage across all three files (B-6), a confirmed clean build and 19/19 test pass (B-7), and an updated progress.md (B-8). The approach is consistent with Phase 1–2 patterns: Tailwind-only styling, pure-SVG diagrams, Zustand state, i18next with `fallbackLng` to handle the ja-kids partial-override pattern. One confirmed blocking issue stops this from being APPROVED: hardcoded Japanese labels inside ComponentPanel bypass the i18n system entirely.

## High-level view

The `mode === 'advanced'` path appends a right-side `<aside>` with `JsonPreviewPanel` and extends the tab list with `components` and `stateGraph` entries. A `useEffect` resets `activeTab` to `'traits'` when switching back to simple mode while on an advanced-only tab — without this, the tabpanel would render an empty content area for a tab that no longer exists in the visible list. All four new panels are pure-SVG or plain Tailwind; no external diagram library was introduced.

The ja-kids locale approach is non-obvious and worth explaining: `fallbackLng: { 'ja-kids': ['ja', 'en'] }` means `ja-kids.json` only overrides the keys that differ from `ja.json` (home copy, simplified editor labels, hiragana UI). Missing keys automatically fall back to `ja`. The `KidsHomeLayout` variant gates on `locale === 'ja-kids'` and matches wireframe #07's large-button/vertical-list structure, except the full-page background color.

The ComponentPanel accordion ships two hardcoded Japanese labels inside the expanded health body, violating the "all display text uses t()" requirement. When the app is in `en` locale, the health component's slider labels display as Japanese with no fallback path.

### Hardcoded Japanese in ComponentPanel

The expanded health body in `ComponentPanel.tsx`:

```tsx
<SliderRow label="体力 (max)" value={20} min={1} max={100} />
<SliderRow label="初期値"    value={20} min={1} max={100} />
```

`SliderRow` renders its `label` prop as visible text in a `<span>`. Both strings are Japanese and bypass `useTranslation` entirely. When the app is in `en` locale, these labels still read as Japanese. Neither string exists in any locale file.

### KidsHomeLayout page background

The wireframe body rule is `background: #FFFBEB`. `AppShell` hardcodes `bg-[#F9FAFB]` with no locale-aware variant. `KidsHomeLayout`'s outer `<div>` has no background class, so the gray shell bleeds through the gutters between the hero section and the project list. The difference between warm yellow and cool gray is visually significant for the target age group and is a named design token in the wireframe, not a placeholder.
